# Utility Helper: Forever 0.1.18 — verification record

Updated: 7 October 2026. Target: WoW: Forever beta, interface 16001.
Local installed client metadata: 1.60.1.70245.

## 0.1.19 combat maintenance buffs

Battle Shout and every configured learned maintenance buff now retain a fixed
secure combat button. When the relevant buff family is missing, the alert can
appear and the prepared button can be clicked during combat; applying the buff
suppresses the alert. Outside combat, only missing maintenance buffs accept
mouse or key input. Strict rest utilities such as bandages, profession tracking
and Warlock stone creation still hide, disable and release bindings in combat.
`tests/maintenance_combat.lua` covers Battle Shout, aura transitions, simultaneous
recovery alerts and strict rest-only isolation. The full Lua 5.1 syntax and
scenario suite passes.

## 0.1.18 Life Tap and spell picker

Life Tap is a learned-only Warlock utility using the new `manahealth` condition.
It activates at or below the mana threshold only while health is above the
health threshold. When the client keeps both values private, two nested native
display curves combine the low-mana and safe-health gates without reading,
comparing or performing arithmetic on secret values.

The custom utility panel now includes Find Spell ID. While armed, it places
temporary non-casting click overlays over recognized spellbook buttons; clicking
a learned spell fills the ID and removes the overlays. Tooltip capture provides
a fallback for other spellbook layouts. The new Low mana + safe health rule is
also available to custom entries and uses the existing health and mana sliders.
`tests/life_tap.lua` covers the threshold boundaries, native private-value path,
picker selection and custom rule creation. The full Lua 5.1 syntax and behavior
suite passes.

## 0.1.17 Paladin blessing ownership and Warlock stones

Paladin self-buff maintenance preserves source ownership: another Paladin's
blessing suppresses the duplicate spell but leaves the character's other learned
blessing choices available. A blessing applied by the character suppresses the
mutually exclusive self choices.

Create Healthstone and Create Soulstone are now outside-combat actions that
activate only when no supported tier of the corresponding stone is in the bags.
A separate outside-combat Soulstone (self) item action applies resurrection
protection to the Warlock and clears when the protection aura is active. The
existing selected-friendly-player Soulstone and low-health Healthstone actions
remain separate. Every action has its own settings entry. `tests/warlock_stones.lua`
checks inventory transitions, fixed self targeting, aura suppression, the ally
action and independent configuration. The full Lua 5.1 syntax and behavior suite
passes.

## 0.1.16 learned self-buffs

All curated maintenance buff families now receive learned-only, clickable
outside-combat self buttons. A level 1 Warlock with Demon Skin receives the
alert immediately when the buff is absent. Existing targeted friendly buff
buttons remain separate. Mutually exclusive families suppress every alternative
after one choice is active, including Paladin blessings and auras, Hunter
aspects, Mage armors, Shaman shields, Warlock armors and Warrior shouts.
`tests/self_buffs.lua` checks level 1 Demon Skin, spell upgrades, self targeting,
independent keybinds, family suppression, friendly-to-self coverage and secure
combat shutdown. The full Lua 5.1 syntax and behavior suite passes.

## 0.1.15 resource tracking

Learned Find Herbs, Find Minerals, Find Fish and Dwarf Find Treasure now share
an outside-combat choice group. When no supported resource tracker is active,
all learned choices appear with independent clicks and keybinds. Once one is
active, every choice is removed. Hunter creature tracking is excluded and does
not suppress the resource choices. `tests/tracking.lua` covers learned filtering,
simultaneous choices, selected-state suppression, unrelated Hunter tracking,
mounted/combat shutdown, binding release and unavailable-API failure behavior.
The full Lua 5.1 syntax and behavior suite passes.

## 0.1.14 Rogue catalogue correction

Sap, Cheap Shot and Pick Pocket have been removed from the Rogue catalogue.
These entries require stealth and therefore appeared only after stealth was
already activated, then disappeared when stealth broke. A regression check
confirms that all three entries remain absent when their spells are learned.

## 0.1.13 punctuation correction

The visible title is now **Utility Helper: Forever** in the TOC, settings,
minimap tooltip, bar caption and chat prefix. Internal folder, frame and
SavedVariables identifiers remain `UtilityHelper` for compatibility. The
minimap regression verifies the requested title and the full suite passes.

## 0.1.11 change — complete

New profiles now default Inactive visibility to 0%. The settings regression
checks a fresh profile at 0%, all adjustable visibility endpoints, and confirms
that a previously saved 37% choice survives settings loading unchanged. The full
Lua 5.1 syntax and behavior suite passes. This is a default-only change; it does
not migrate or overwrite existing characters' saved visibility values.

## What these checks do not prove

The user confirmed the 0.1.6 Scare Beast fix at 0% inactive visibility.
The user observed the 0.1.8 bandage icon at 100% health and rejected that fallback.
The owner has confirmed the corrected bandage threshold display and accepted
the release. Separately recorded native evidence for every First Aid interaction
and expanded class scenario is absent; this is not a pending testing request.
The requested fully clickable low-health-only bandage remains limited by the beta:
private health may drive native presentation but cannot choose protected input.
Detailed native recordings of every animated-outline size/intensity and GCD
scenario are not available; do not infer exhaustive coverage from acceptance.
`/uh why` reports the most recent public decision/reason without secret values.

Detailed native evidence for every secure mouse/binding transition and
pet-healing channel variant is not recorded here. Those details are nonblocking
disclosures; the owner has cleared the addon and no repeat check is scheduled.

The harness implements only the parts of the WoW API used by the add-on.
It represents secret values with objects that reject arithmetic/comparisons;
this does **not** fully reproduce native secret scalars, taint, secure click
execution, protected anchors or native display rendering. A mock pass is not
proof of live beta compatibility or successful spell casting.

The user supplied a live screenshot of a 0.1.0 execution-time warning (Count 100,
27 September 2026 at 11:07:02). Its stack was empty. The recursive event path
was reproduced in the harness; that is evidence of a real defect, not definitive
proof that it was the only cause of this specific native warning. Live confirmation
isolating that fix from every possible cause is not separately recorded; this is
not a task to reopen the accepted startup behavior absent a credible new issue.

The user then supplied a native 0.1.1 startup error at 11:20:46 identifying
`LEARNED_SPELL_IN_TAB` as unknown. Version 0.1.2 removes it and guards all event
registration. The exact failure is covered by the harness; live confirmation
of that error's removal was followed by the user's "All looks good" report and
screenshots showing the settings and working utility bar. This supports successful
startup, but does not establish every combat scenario or a long-running timeout test.
The user then supplied a 0.1.3 screenshot showing a tooltip over an invisible
Mend Pet button. Version 0.1.4 addresses that defect with a dedicated tooltip
whose opacity follows the alert. Exhaustive combat/all-class native coverage is
not recorded. The owner's acceptance stands; no routine repeat tests are pending.

This project task performed no agent-driven in-game checks, controlled no live
character, initiated no combat and used no consumables. Owner acceptance and
